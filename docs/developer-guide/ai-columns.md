# Asynchronous AI columns

AI columns are nullable stored results generated by `AI_COMPLETE` or `AI_EMBED`
after the transaction that changes their inputs commits. Register the model and
endpoint through `DBMS_AI_SERVICE` before declaring the column.

```sql
CREATE TABLE docs (
  id BIGINT PRIMARY KEY,
  body TEXT,
  summary TEXT AI COLUMN (AI_COMPLETE('text_model', body))
    WITH (sync_mode='async', max_retries=2),
  embedding VECTOR(4) AI COLUMN (AI_EMBED('embed_model', body))
    WITH (sync_mode='async', max_retries=2)
);

INSERT INTO docs(id, body) VALUES (1, 'Some text');
SHOW AI COLUMNS FROM docs;
ALTER TABLE docs RETRY AI COLUMN summary WHERE status = 'FAILED' AND id = 1;
SET SESSION ai_column_strict_read = ON;
SELECT summary FROM docs;
```

Only asynchronous generation is supported. Dependencies must be ordinary
columns in the same table. Explicit embedding dimensions must match the VECTOR
dimension. Business SQL, including stored procedures, cannot assign AI results.
The ordinary write path invalidates affected results, updates vector indexes,
and creates persistent tasks within the business transaction. Rollback undoes
all three changes. Updates to unrelated columns do not create tasks.

Each AI column has hidden state, request ID, and definition-version columns.
`oceanbase.__all_ai_column` exposes definitions; `__all_ai_column_task` holds
pending work, staged results, retry counts, and leases. Workers claim a row's
request group, evaluate its expressions through the SQL engine without holding
business-row locks during HTTP calls, validate the outputs, and publish all
terminal results in one transaction. Publication checks both the lease owner
and each column's request ID and definition version. Superseded and deleted
rows cannot be recreated by a late response. Expired leases recover interrupted
work; a response lost before staging can cause another model call.

PENDING and FAILED results read as NULL by default. READY results may also be
NULL, for example for a NULL embedding input. Strict reads use the stored state of
every referenced AI column across its table, including rows excluded by WHERE
or LIMIT. Statements referencing only ordinary columns remain available.
In a RETRY predicate, unquoted `status` is the selected AI column's state
(`PENDING`, `READY`, or `FAILED`); backtick-quoted `status` is a business column.

## Validation

Build the server and the `sql_tests` / `share_tests` CMake targets, then run
`ctest --output-on-failure`. SQL coverage lives in
`tools/deploy/mysql_test/test_suite/ai_column/`:

- `ai_column_ddl`: persisted definitions and invalid declarations.
- `ai_column_t1_dml`: transaction boundaries, dependency changes, keys, and cleanup.
- `ai_column_worker`: typed output, group publication, retries, and stale responses.
- `ai_column_retry_strict`: conditional retry and column-wide strict reads.
- `ai_column_vector_index`: VSAG/ANN invalidation, regeneration, and rollback.
- `ai_column_regression`: composite Unicode keys, stored procedures, backfill and
  changed definitions, READY NULL, and ordinary writes during strict reads.

Run these with mysqltest from `tools/deploy` and compare with `r/mysql/*.result`.
The scripts manage their local mock services. The AI function enhancement suite
additionally needs a protocol-compatible mock on port 8000. No real credentials
or model inference are required.
